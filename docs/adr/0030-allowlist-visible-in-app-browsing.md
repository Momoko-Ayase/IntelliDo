# 对可见的应用内浏览采用允许列表

已识别的 LINUX DO 路由进行原生导航；不兼容的主站路由以及位于随版本发布的精确 HTTPS Origin 允许列表中的辅助服务，可在可见的 JCEF 浏览器中打开。通配符、页面链接、重定向和远程配置均不能授予信任；离开允许列表的导航在系统浏览器中打开，更改允许列表必须发布 IntelliDo 更新。受信任浏览器标签页可共享 JCEF 按 Origin 隔离的 Cookie 配置以使用 LINUX DO SSO 或 OAuth，但不获得原生桥接、本地文件访问或特权 IntelliDo API。它们使用受限浏览器控件，始终显示准确 Origin，并提供“后退”“前进”“重新载入”“在外部打开”和“关闭”，但没有可编辑的通用地址栏。

精确 `https://linux.do/` Origin 上的所有不受支持路由均在此应用内浏览器中打开，包括超出 IntelliDo 原生 Level 3 能力上限但成员有权访问的工作人员路由。

Web 弹窗绝不创建第二个 IntelliDo 窗口。身份验证弹窗使用主窗口内的临时模态 JCEF 视图；允许列表中的受信任服务弹窗成为受限的应用内浏览器标签页；其余弹窗全部在系统浏览器中打开。模态身份验证期间始终显示准确 Origin。

摄像头、麦克风、位置、屏幕捕获和广泛的剪贴板访问默认拒绝。只有登录页和允许列表中的受信任服务页面可以显示明确的一次性权限请求；授权绝不静默发放或永久记住。LINUX DO 身份验证可使用 WebAuthn 或 Passkey，而无需授予无关设备权限。

外部 OAuth Origin 是与流程绑定的独立例外，而非受信任服务 Origin：它们只能在成员于 LINUX DO 登录页发起操作后出现，不获得原生桥接，并且必须返回 LINUX DO。无关导航在系统浏览器中打开。

每个链接在鼠标悬停或键盘聚焦时显示其规范目标。HTTPS 遵循普通的原生、受信任浏览器或系统浏览器路由规则；HTTP 和 `mailto:` 需要确认并显示准确目标。`file:`、`javascript:`、`data:` 及未知自定义 Scheme 均被阻止，只提供 **复制链接**。

所有源自 JCEF 的下载均由原生附件下载流程拦截，绝不能自动打开或执行。
