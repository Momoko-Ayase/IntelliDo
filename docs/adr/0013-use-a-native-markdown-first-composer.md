# 使用原生、Markdown 优先的编辑器

IntelliDo 以基于 IntelliJ 的 Markdown 源码编辑器作为唯一创作模型，提供语法高亮、提及与 Emoji 补全、格式化操作、引用插入，并通过原生帖子渲染器提供实时预览。上传支持原生文件选择、拖放和从剪贴板粘贴图片，并逐文件显示进度、取消、重试、服务器错误及最终 Markdown 插入；发布或关闭不能与未完成的传输产生竞态。所选字节保持原样传输，缩放、转码、元数据处理和拒绝均交由 LINUX DO，而不是静默改写媒体或文档。回复使用停靠在当前话题标签页内、可调整大小且非模态的编辑器，使对话上下文持续可见；打开编辑器会固定预览标签页。编辑帖子复用该停靠编辑器，并在保留周边上下文的同时原位预览所选帖子。每个话题标签页最多只有一个活跃编辑器；切换创作任务前必须保存或丢弃未解决的更改。新话题使用专用的固定标签页，包含元数据、插件字段、编辑器和预览；发布成功后，该编辑器标签页由新建话题替换。初始版本不并行实现 WYSIWYG 模型，从而避免有损往返转换和重复的编辑器复杂度，同时保留 Discourse 的原始帖子源码。

插入图片时使用上传文件名生成 Markdown 替代文本，与常规 Discourse 创作流程一致。IntelliDo 不增加独立的替代文本表单或空文本警告；作者可直接修改 Markdown。

编辑器可以使用内置的离线 IntelliJ 拼写检查和设备本地词典。它不集成云端语法、改写或写作助手服务，也绝不会把未发布文本发送给外部提供方。

如果帖子或服务器草稿在编辑器载入后发生变化，发布将暂停。原生冲突视图通过合并编辑器呈现服务器版本和本地版本，并提供明确的 **复制本地文本** 与 **重新载入服务器版本** 恢复路径；IntelliDo 永远不会静默覆盖任一版本。
