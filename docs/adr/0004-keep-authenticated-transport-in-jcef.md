# 将身份验证传输保留在 JCEF 中

IntelliDo 将 LINUX DO 会话保留在 JCEF 内，并在该浏览器上下文中执行已验证身份的社区请求，再通过窄接口桥接把结构化结果交给原生 UI。它不会把会话 Cookie 导出到独立的 JVM HTTP 客户端，从而避免重复维护 CSRF 与 Cloudflare 状态，并将 Web 技术限制在身份验证和传输边界，而非可见的核心体验中。

即使某种 JCEF 身份验证方式不可用，也禁止导入系统浏览器 Cookie 或回退到原生用户名、密码输入。

匿名公开的 LINUX DO 请求同样通过 JCEF 浏览器传输执行，但不携带已验证身份的会话。原生 UI 使用相同的、经过验证的结构化桥接结果；IntelliDo 不维护并行的 JVM Discourse 传输实现。

原生功能只使用结构化服务器响应，不抓取已渲染页面的 DOM。隔离的 Connect 适配器是唯一有记录的例外。
