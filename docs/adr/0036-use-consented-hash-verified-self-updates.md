# 使用经同意且通过哈希验证的自更新

IntelliDo 自动检查 HTTPS 更新源并原生展示发布说明，但只有成员同意后才下载；安装前根据已发布的加密哈希验证产物，并在明确重启时应用更新。它绝不静默替换正在运行的安装，更新检查除传输交付固有暴露的信息外，不携带任何分析 Payload。

应用内更新器只提供稳定版。Nightly 构建可以发布供手动安装，但 IntelliDo 不提供 Nightly 更新通道，也不会自动把现有安装切换到 Nightly。

Nightly 安装使用独立产品身份，并与稳定版 IntelliDo 分离设置、缓存、插件和会话存储。跨通道单实例锁防止稳定版与 Nightly 进程同时运行，避免重复通知和阅读会话。

Nightly 构建完全禁用自更新，只提供指向规范 GitHub Nightly 产物的链接。应用内安装只允许稳定版到稳定版的替换。

更新变更 IntelliJ Platform 基线前，IntelliDo 会针对目标构建预检已安装插件，列出所有已知不兼容项，并要求确认后才禁用受影响插件并继续。更新绝不静默移除插件。

更新后的稳定构建必须通过首次启动健康检查，才能最终替换旧构建。若启动失败，IntelliDo 自动把应用二进制回滚至上一构建，同时保留兼容偏好和受信任会话数据；它不恢复标签页或内容状态。若问题仍指向非捆绑插件，恢复后的构建提供安全模式。

更新始终可选。更新服务不具备远程强制最低版本开关，不能禁用原本可用的安装。IntelliDo 可以对紧急安全版本给出显著建议；与服务器不兼容的功能则遵循普通组件级错误行为，而不是阻塞整个应用。

由于项目目前没有商业签名证书，官方产物暂不进行代码签名或公证。哈希验证能发现意外损坏，但缺少独立验证的签名时不能证明发布者身份；必须清楚说明平台警告和这一限制。获得合适证书后可重新评估代码签名。
